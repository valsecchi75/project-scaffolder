# Level 1 — Platform decision (`/4-build`, first run)

Read this when `wiki/tech-stack.md` still says the platform is pending, or when the platform is decided but `.claude/skills/verify/SKILL.md` is missing (projects set up before it existed: write it as in step 4, before anything else).

1. Dispatch `project-scaffolder:architect` for a platform decision, pointing it to the brief's constraints, `wiki/architecture.md`, the design registry, the working agreements' reference projects, the external services that need keys (working agreements, `.env.example`), and the phase-4 lines of `raw/parking-lot.md` (solutions the user volunteered in phase 1: each is weighed against the constraints and named adopted or rejected in the decision, never adopted silently).
2. Present its two or three options with the recommendation and ask the user to choose. This is a gate in every interaction mode: it is irreversible and has cost. A client-only option that would need a key on the user's device is not an option: the architect's rule gives it a proxy or a keyless service.
3. Record the choice as a `DEC-NNN`, fill `wiki/tech-stack.md` (language, framework, hosting, data store, the exact build, test, lint, type-check and audit commands, and the build output folder the release gate scans for keys), replace the placeholder of the `## Commands` section in the project's `CLAUDE.md` with the same commands (install, run, full suite, one test file, type check, lint), and update `wiki/architecture.md` with the layers.
4. Write `.claude/skills/verify/SKILL.md` from `templates/verify-skill.md` (in this skill's folder) with those commands. The folder is `verify`, without the project prefix: from Claude Code v2.1.286 a project skill with that name makes Claude run it before each commit, and it replaces the bundled `/verify` in this repository. Never give it `disable-model-invocation` (the commit instruction then stops). It counts from the next session and is guidance, not a block: the verifier still runs it on every task. When the commands in `wiki/tech-stack.md` change, update it and the `CLAUDE.md` Commands section in the same edit.
5. Generate the stack skills with `/skill-new` (framework patterns, deployment) and add them, with `verify`, to `wiki/skills-map.md`.
6. The project skeleton is the first activity of the first milestone, not part of this level.
